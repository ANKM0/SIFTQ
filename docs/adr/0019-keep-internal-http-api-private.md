# ADR 0019: Keep internal HTTP API private

## 決定

- API は公開しない。内部 IF として実装する。
- HTML UI の endpoint と内部 API は `/api` prefix で分離する。

### 決定の理由

- 現状は個人利用で、外部クライアントやサードパーティ連携の要件がない。
- 認証が未実装の段階で公開すると、所有者確認やアクセス制御ができない。
- 公開 API にはバージョニング、ドキュメント、レート制限、後方互換の運用コストが付く。

## 不採用

- API の外部公開
  - 認証・互換性・運用コストが要件を超える。外部連携要件ができた時点で再検討する。

## 補足情報

### 背景

- 将来の CLI は、この内部 API を認証付きで呼ぶ想定。

### 制約事項

- 認証・レート制限はこの ADR の対象外とする。
- `/api` の route 契約は ADR 0021 に従う。
