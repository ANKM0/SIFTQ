# ADR 0056: 失敗した楽観的DnD更新をロールバックする

## 決定

- DnD操作は楽観的UIとして扱い、永続化に失敗した場合は正本に合わせて表示を元に戻し、失敗をユーザーへ通知する。

### 決定の理由

- 表示と正本データの不一致を失敗後に残さないため。

## 不採用

- 失敗時に表示を維持する方式
  - 表示が正本と異なる状態を残すため。

## 補足情報

### 背景

- ADR 0008から、version競合検出とは別に、クライアント側の楽観表示の失敗処理を分離して記録する。

### 制約事項

- 永続化処理の競合判定はADR 0055に従う。
- 通知の共通表示ルールはADR 0028に従う。

### 限界と再検討条件

- 限界: 自動的な競合マージや操作履歴の復元は扱わない。
- 再検討条件: 失敗操作の再試行や履歴復元が必要になった場合。
