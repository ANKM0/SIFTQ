# ADR 0035: 画面遷移図の生成ツールとして、D2を採用する

## 決定

- 画面遷移図の生成ツールとして、D2を採用する
- 画面遷移図は FSM で表現し、状態ノードは画面、エッジラベルは操作とする。

### 決定の理由

- 日本語が文字化け・はみ出すなどのトラブルが無かったため
- marmaidと比較して図がきれいに見えたため
- D2 は FSM の丸ノードとラベル付きエッジを 1 つの source で直接表現でき、静的 SVG を文書へ組み込みやすいため。
- 正本と生成物を 1 方式に絞り、Mermaid / D3.js の比較版が混在する状態を解消するため。

## 不採用

- Mermaid flowchart の丸ノード `((...))`
  - `mmdc` で生成できるが、同等の FSM を複数ツールで管理する理由がなく、レイアウト設定が分散するため。
- Mermaid + ELK で操作をノードとして明示する
  - 操作がノードになり FSM の形と異なるため。
- D3.js force-directed graph
  - ドラッグ再配置は有用だが、文書の正本としては CDN 依存があり、静的画像化が別途必要になるため。

## 補足情報

### 背景

- 図の作成ツールとして、marmaidを使用していたが、構文が複雑・日本語の表現が苦手(よくはみ出す)などの課題があった。
- 画面遷移図を FSM で記述する際にmarmaidだと、上記日本語問題が再発し修正にtokenと時間を取られることが懸念されたため、代替手段を検討した。

### 制約事項

- なし
