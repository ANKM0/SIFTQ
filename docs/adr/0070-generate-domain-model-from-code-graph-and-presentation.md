# ADR 0070: ドメインモデルをコード由来の自動グラフと表現層から生成する

## 決定
<!-- 決定事項、採用した内容とその理由を記載 -->

- ドメインモデルを、コードから機械的に抽出できる関係（自動部分）と、人が与える表現・業務フロー（表現部分）に分ける。
- 自動部分はコードを読み取り部分モデルを出力するコマンドで生成し、表現部分は人が編集する。両者をマージした結果を正本モデルとし、手編集しない。
- 図は従来どおり正本モデルから生成する。

### 決定の理由
<!-- 決定事項、採用した内容の理由を記載 -->

- 構造のうちコードから一意に決まる部分は、人手で写すと乖離し、レビューで見落とすため。
- 人が与えるべきは意味（説明・業務フロー・不変条件の参照）であり、物理的な対応関係はコードが持つため。
- 正本モデルを生成物にしても、マージ規則を固定すれば再現でき、schema と突き合わせで検証できるため。

## 不採用
<!-- 採用しなかった内容とその理由を記載 -->

- 正本モデルを手書きのまま単一ソースとして維持する
  - コードから決まる部分の乖離を人手で防ぐ必要があり、adapter の事後検証だけでは修正コストが残るため。
- 自動部分のみを正本にする
  - 説明・業務フロー・不変条件の参照など、コードから導けない意味を表現できないため。
- 表現層と自動層を項目単位で深くマージする
  - マージ規則が複雑になり、どの層が値の出所か追えなくなるため。辞書は層単位、一覧は追加・削除の上書きに限定する。

## 補足情報

### 背景
<!-- 解決する問題の背景やチームの状況などの戦略。 -->

- ドメインモデルの正本を 1 ファイルに集約し、図を生成する方針は ADR 0044 で定めた。
- 集約後にコードとモデルの突き合わせ検証を追加したが、コードから決まる関係をモデル側で人手により写す作業は残っていた。

### 制約事項
<!-- ライブラリや設計の変更におけるトレードオフやできない事とその理由。 -->

- 抽出コマンドはコードの言語に依存させない。任意の実行ファイルが部分モデルを出力できればよい。
- 表現層に自動部分と同じ辞書キーを書いた場合は表現層が優先する。項目単位の合成は行わない。
- 抽出できない意味（説明・業務フロー・不変条件の参照）は表現層に残す。

### 限界と再検討条件
<!-- 確認していない範囲と、どの前提が変わったら見直すかを記載。 -->

- 限界: 抽出は静的な字面に基づき、動的に決まる意味や分類までは導かない。表現層の意味の妥当性は検証しない。
- 再検討条件: 抽出できない意味が増え表現層が肥大した時、または同期検査が形骸化した時。
