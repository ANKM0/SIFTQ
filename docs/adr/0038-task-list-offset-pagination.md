# ADR 0038: Task一覧のページングにoffset方式を採用する

## 決定

- Task一覧のページ分割にoffset方式を採用する。1ページ25件固定でサーバー側sliceし、ページ指定は`?page=`で行う。
- 判定単位はstatus絞り込み後の件数とする。
- 不正なページ指定は1ページ目へフォールバックし、範囲超過は最終ページへクランプする。

### 決定の理由

- Task取得が全件list＋メモリfilterであり、cursorの利点（大量件数での安定走査）が活きないため。
- 既存の`?status=`と同じquery方式で最小変更に収まり、URLでページを共有できるため。

## 不採用

- cursor方式（`?after=<id>`）
  - 追加・削除時の境界安定性は高いが、任意ページへの直接ジャンプができない。現規模（数十件）では過剰なため。
- 1ページあたり件数の変更可能化
  - Issue #369のScope外のため。25件固定とする。

## 補足情報

### 背景

- Task一覧は全件表示であり、件数増加で一覧性と操作性が低下する。25件を境にページを分ける（Issue #369）。

### 制約事項

- 件数が数百規模へ成長し全件取得が重くなった場合は、cursor方式への移行を再検討する。
- スマホ向けのページング操作（ボタン押下・横スライド移動）は本決定の対象外とする。利用実態を見て別途検討し、Issueは現時点では作成しない。
