# ADR 0069: セッションを age で暗号化して公開リポジトリへバックアップする

## 決定

- Codex と opencode の会話セッションを、クライアント側で zstd 圧縮してから age（X25519）で暗号化し、公開リポジトリの専用ディレクトリへ commit する。
- 秘密鍵はリポジトリ外に置いて別経路で保管し、追跡する鍵素材は recipient 公開鍵だけにする。復号鍵は環境変数から注入し、リポジトリや CI へは置かない。
- バックアップと復元は自動実行せず、利用者が指定したタイミングで手動実行する。復元はタスクとして用意する。
- Codex はセッション単位のファイル、opencode はデータベース全体のスナップショットとして保存する。opencode のスナップショットはイベント記録を含む全テーブルを対象にする。
- 暗号化アーカイブは git 履歴へ永続する前提で扱い、実行頻度をそのままリポジトリ増加量として受け入れる。

### 決定の理由

- PC 障害でローカルのセッションが失われても、公開リポジトリから復元できるようにするため。
- 公開先へ内容を露出させないため、平文を置かず、秘密鍵をリポジトリへ入れない必要があるため。
- 同期の自動化は増加量と費用を制御しにくいため、実行タイミングを利用者が指定するため。
- opencode の標準 export はイベント記録を含まず、会話の再現に不足するため、全テーブルのスナップショットを採用するため。

## 不採用

- セッションを平文または可逆な難読化で保存する
  - 公開リポジトリへ内容が露出するため。
- 秘密鍵をリポジトリや CI に置く
  - 公開鍵暗号の前提が崩れ、暗号化の意味がなくなるため。
- 自動スケジューリングや CI からの定期同期
  - 無人の増加を招き、費用と履歴量を制御しにくいため。
- opencode の標準 export だけを使う
  - イベント記録が含まれず、会話の再現に不足するため。

## 補足情報

### 背景

- ローカルのセッションを改善分析へ使いたいが、リポジトリは公開で平文を push できない。
- 暗号化バックアップの方針は FEAT-20260822-001 と LRN-20260822-002 で既に決まっている。
- 秘密情報を環境変数経由で扱い Git へ置かない方針は ADR 0058 と、追跡パスを明示的に許可する方針は ADR 0041 と整合する。

### 制約事項

- 追跡する鍵素材は recipient 公開鍵だけで、秘密鍵はリポジトリに存在しない。
- 初回のバックアップは codex と opencode を合わせて約 200–230MB になる見込みで、以降は実行頻度に比例して増加する。
- 暗号文に加えて、日付・ファイル名・サイズなどのメタデータは公開される。
- 復号鍵を失うと履歴を復元できないため、鍵の別経路バックアップが必須となる。

### 限界と再検討条件

- 限界: 公開メタデータの秘匿性、復号鍵の長期保管とローテーション、履歴増加の抑制は未検証。
- 再検討条件: リポジトリ増加量、暗号方式、または鍵保管方法が変わった場合。
