# ADR 0054: 副作用境界の抽象化を最小化する

## 決定

- interfaceはusecaseと副作用の境界に必要な場合だけ定義し、将来の差し替えだけを理由に先行して作らない。
- 層と抽象化は、副作用境界の責務に必要な最小限に留める。
- repository adapterは副作用境界の契約を通じて利用し、domainの一般的な契約にはしない。

### 決定の理由

- 境界に必要な契約だけを置き、責務を明確にするため。
- 実装形式を固定しすぎず、必要な契約と責務だけを明確にするため。

## 不採用

- すべての実装にinterfaceを先行して付ける
  - 実際の差し替え点がない抽象化を増やすため。
- 実装形式を将来の拡張のために先に固定する
  - 実際の責務に対して過剰な構造を持ち込むため。

## 補足情報

### 背景

- ADR 0006から、副作用境界の抽象化とアダプター実装形式を分離して記録する。

### 制約事項

- repository契約は副作用境界として扱い、domainの一般的なinterfaceにはしない。
- 実際に複数実装が必要になった場合は、必要な契約だけを追加する。
- 親ADRにあった具体的な生成形式は実装詳細として扱い、アーキテクチャ文書で管理する。

### 限界と再検討条件

- 限界: 複雑なライフサイクルや共有状態が必要になった場合、object literalだけでは表現しにくい。
- 再検討条件: 複数の実装、明確なライフサイクル、または共有状態の管理が必要になった場合。
