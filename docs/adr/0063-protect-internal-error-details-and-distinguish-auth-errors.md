# ADR 0063: 内部エラー詳細を隠し認証エラーを区別する

## 決定

- サーバー内部エラーの詳細はclientへ返さず、ログにだけ残す。
- 401はログインまたは再認証へ誘導し、403は権限エラーとして表示してログインへ戻さない。

### 決定の理由

- SQL、stack trace、内部実装をclientへ露出させないため。
- 認証失敗と権限不足を区別し、無意味な再認証ループを避けるため。

## 不採用

- 内部エラー詳細をclientへ返す方式
  - 情報漏えいにつながるため。
- 401と403を同じログイン誘導にする方式
  - 再認証しても権限不足は解決しないため。

## 補足情報

### 背景

- ADR 0025から、error representationとsecurity・authentication behaviorを分離して記録する。

### 制約事項

- 認証方式はADR 0032、将来の移行先はADR 0036に従う。
- エラー形式とstatus分類はADR 0023とADR 0024に従う。

### 限界と再検討条件

- 限界: 認証providerやユーザー管理の方式自体は決めない。
- 再検討条件: 認証方式、権限モデル、またはエラーclientが変わった場合。
