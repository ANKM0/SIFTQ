# ADR 0066: レスポンシブ対応のブレークポイントを定める

## 決定

- レスポンシブ対応はモバイルファーストで設計する。
- ビューポート幅の閾値は `40rem (640px)`、`48rem (768px)`、`64rem (1024px)`、`80rem (1280px)` とする。
- `40rem` 未満を標準の狭い画面とし、各閾値以上で必要なレイアウトを段階的に拡張する。
- 閾値は端末名ではなくビューポート幅で判断し、`rem`を使用する。

### 決定の理由

- MDNは固定の標準ブレークポイントを定めておらず、コンテンツが窮屈になる位置でブレークポイントを設定し、相対単位を使う方針を示しているため。
- Tailwind CSSで広く使われている標準値と一致し、チーム内で説明・再利用しやすいため。
- 既存の `640px` のレスポンシブ指定と整合し、移行時の判断を増やさないため。
- 現在の画面構成では `1280px` を超える幅に専用レイアウトを追加する必要性がなく、`1536px` の閾値は採用しないため。

## 不採用

- 端末名や特定機種の画面幅を基準にした閾値
  - 端末の多様化に追従できず、未知の画面幅を扱えないため。
- MDNの例にある `600px` や `1200px` の組
  - 具体的な標準値ではなく、記事内のレイアウト例を示す値に過ぎないため。
- `96rem (1536px)` の閾値
  - 現在の画面構成に専用レイアウトがなく、不要な分岐を増やすため。

## 補足情報

### 背景

- スマートフォンなど狭い画面で、ナビゲーション、フォーム、一覧、マトリクスが窮屈にならないレスポンシブ対応を進める。
- 画面ごとに異なる閾値を作らず、横断的に参照できる基準を定める。

### 制約事項

- 閾値はレイアウト変更の基準であり、すべてのコンポーネントが各閾値で必ず変更されることを意味しない。
- レイアウトがコンテンツによって先に破綻する場合は、端末分類を追加せず、該当コンポーネントの設計を見直す。

### 限界と再検討条件

- 限界: 採用値が他のブレークポイント体系よりユーザビリティに優れることは、実装前のため確認していない。
- 再検討条件: 主要画面の検証で不合格が発生した場合、または画面構成・コンテンツ幅の前提が変わった場合。
