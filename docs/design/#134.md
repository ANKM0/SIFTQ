# Design Doc #134: Loop Engineering Implementation Policy

## 目的

LLM エージェントによる自動開発を、XP / agile の feedback loop として実行できるようにする。

## ゴール

- GitHub Issue を起点に taqt task を作成し、実行状態を管理する。
- loop 定義を YAML または JSON で宣言し、runner が検証、観測、判断、再試行、停止を管理する。
- GitHub 監視、同期、PR 作成などの外部連携を script adapter として扱う。

## ノンゴール

- GitHub Issue の要求、CUJ、AC/DoD を taqt 側へ移すこと。
- すべての外部サービス連携を loop runner に直接組み込むこと。
- agent の具体的な prompt や model 選定を固定すること。

## 背景

SIFTQ では、LLM エージェントによる自動開発を feedback loop として扱う。
この方針を taqt 実装に落とし込み、GitHub Issue を要求と議論の正本、taqt task を実行状態の管理単位として分ける。

## 制約事項

- GitHub Issue を要求、CUJ、AC/DoD、議論の正本とする。
- taqt task は GitHub Issue を source として作成する。
- taqt 実装は `.taqt/`、補助 script は `scripts/` を基準にする。
- GitHub 監視や外部サービス同期は script adapter として扱う。

## 解決する課題

- agent 実行の step、観測結果、再試行、停止理由を追跡できない。
- GitHub Issue と taqt task の責務境界が曖昧になりやすい。
- branch、commit、push、PR 作成を loop 実行結果と紐づけて再現する必要がある。

## 提案する設計

### Lifespan

taqt task は GitHub Issue を source として作成し、worker、phase、run state などの実行状態を管理する。

| 段階 | 主体 | 内容 |
| --- | --- | --- |
| 1. 要求作成 | 人間 | 達成したい価値、問題、制約を作成する。 |
| 2. CUJ 作成 | 人間 + 仕様化支援 agent | Critical User Journey、ユーザーストーリー、受け入れ条件、DoD を具体化する。 |
| 3. GitHub Issue 作成 | 人間 / script adapter | 要求、CUJ、AC/DoD、DoD を GitHub Issue として登録する。Issue が管理単位の正本になる。 |
| 4. taqt task 作成 | taqt / script adapter | GitHub Issue を source として taqt task を作成する。taqt task は実行状態と worker 管理を担当する。 |
| 5. loop 開始 | taqt worker | `pending` task を取得し、対応する loop 定義を runner に渡す。 |
| 6. 設計仮説 | Design Agent | Issue の AC/DoD を満たすための設計仮説、影響範囲、実装分割を作る。 |
| 7. テスト作成 | Test Author Agent | 受け入れ条件と設計仮説から、失敗するテストや回帰テストを作る。 |
| 8. 実装 | Implementation Agent | テストを満たす最小実装と必要なリファクタリングを行う。 |
| 9. 観測 | loop runner / script | test、typecheck、lint、build などを実行し、結果を observation event にする。 |
| 10. 判断 | Policy Router / Decision Agent | 明白な失敗は規則で戻り先を決め、不明な失敗だけ Decision Agent が分類する。 |
| 11. 修正 loop | 対応 agent | 実装、テスト、設計のどこへ戻すかに従い、修正して再び観測する。 |
| 12. 独立検証 | Checker Agent | 仕様、テスト、実装の整合性と完了条件を読み取り専用で検証する。 |
| 13. branch / commit | taqt / script adapter | Issue 用 branch または worktree を用意し、検証済み差分を commit する。 |
| 14. push / PR 作成 | taqt / script adapter | branch を push し、GitHub PR を作成または更新する。 |
| 15. 完了同期 | taqt / script adapter | taqt task を `done` にし、GitHub Issue、comment、PR へ結果を反映する。 |
| 16. エスカレーション | Decision Agent -> 人間 | 仕様矛盾、プロダクト判断、権限外変更、繰り返し失敗を人間へ渡す。 |

### 実装する Script

| Script | 役割 | 入力 | 出力 |
| --- | --- | --- | --- |
| `.taqt/scripts/taqt/github_watch.py` | GitHub Issue を監視し、対象 Issue を taqt task として登録・更新する。 | GitHub Issue query、label 条件、taqt task store | taqt task draft/update |
| `.taqt/scripts/taqt/github_sync.py` | taqt task の状態を GitHub label/comment/PR へ反映する。 | taqt task、run state、sync 設定 | GitHub label/comment/PR update |
| `.taqt/scripts/taqt/task_create.py` | GitHub Issue を source として taqt task を作成する。 | GitHub Issue ref、loop id、priority、input path | taqt task |
| `.taqt/scripts/taqt/task_run.py` | taqt task を 1 件取得し、対応する loop runner を起動する。 | task id、worker id、loop definition | run directory、task state update |
| `.taqt/scripts/taqt/git_worktree.py` | Issue 用 branch / worktree を作成する。 | taqt task、base branch、worktree root | git worktree |
| `.taqt/scripts/taqt/git_commit.py` | loop 実行後の差分を commit する。 | taqt task、workspace、commit message | git commit |
| `.taqt/scripts/taqt/git_push.py` | Issue branch を remote に push する。 | taqt task、workspace、remote | pushed branch |
| `.taqt/scripts/taqt/github_pr.py` | Issue branch から GitHub PR を作成する。 | taqt task、base branch、draft flag | GitHub PR |
| `.taqt/scripts/loop/runner.py` | loop 定義を解釈し、step 遷移、agent 呼び出し、observe、verify を実行する。 | `loop.yaml` / `loop.json`、task input | `state.json`、`events.jsonl`、artifacts |
| `.taqt/scripts/loop/context.py` | 各 step の prompt に渡す context を組み立てる。 | task、loop step、repository state、previous events | agent context |
| `.taqt/scripts/loop/observe.py` | test、lint、build、任意 command を実行し、結果を構造化する。 | command list、workspace | observation event |
| `.taqt/scripts/loop/policy.py` | observation と agent output を feedback 種別へ分類し、次 step を決める。 | observation event、routes、run state | next step |
| `.taqt/scripts/loop/llm.py` | LLM / Codex CLI などの agent adapter を提供する。 | agent role、prompt、context、tool policy | agent response |
| `.taqt/scripts/loop/guard.py` | artifact write scope、危険 command、予算、最大 iteration を検査する。 | loop definition、workspace diff、command | pass/block result |
| `.taqt/scripts/loop/state.py` | run state と append-only event log を保存・復元する。 | state transition、event | `state.json`、`events.jsonl` |

### taqt 定義

| 定義 | YAML key | 概要 |
| --- | --- | --- |
| Task identity | `id` | taqt task の一意 ID。例: `FEATURE-123`。 |
| Source | `source` | 正本となる GitHub Issue への参照。 |
| Status | `status` | task 全体の状態。`pending`、`running`、`blocked`、`done`、`failed`。 |
| Phase | `phase` | 現在の loop 上の位置。例: `spec`、`test`、`implement`、`verify`、`review`、`human`。 |
| Priority | `priority` | worker が取得する優先度。例: `low`、`normal`、`high`。 |
| Loop | `loop` | 使用する loop 定義 ID。例: `development_feedback_loop`。 |
| Branch summary | `branch_summary` | Issue branch 名の `{変更概要}` に使う短い英語の説明。例: `add_user`。 |
| Input | `input` | requirements、task body、関連 file など loop runner に渡す入力。 |
| Run reference | `run` | 現在または最後の run id、`state.json`、`events.jsonl` の参照。 |
| Worker | `worker` | 実行中 worker の ID、開始時刻、heartbeat。 |
| Blocked reason | `blocked_reason` | human handoff や仕様不足などで停止した理由。 |

## 採用しなかった案

- GitHub Issue だけで実行状態を管理する。
  - worker、phase、run state、観測 event を Issue 上で管理すると、再試行や自動処理の状態が追いにくくなるため。
- loop runner が GitHub 監視や同期を直接担当する。
  - runner の責務が広がり、外部連携の変更が loop 実行ロジックへ波及するため。

## 影響範囲

- `.taqt/scripts/taqt/`

- taqt task schema と task store の対象 pytest を実行する。
- loop runner、policy、state の単体テストを追加後に実行する。
- Markdown 変更時は `task ci:markdown` を実行する。

- agent adapter の最初の対応先。
