# Design Doc #165: Loop YAML role-specific model and reasoning effort

## 目的

loop YAML で agent と llm step ごとに Codex の model と reasoning effort を指定できるようにする。development feedback loop では、設計・検証・実装・checker の役割ごとに Codex の model と reasoning effort を割り当てる。

## ゴール

- agent と llm step の `model`、`reasoning_effort` を YAML で指定できる。
- 不正な `reasoning_effort` は Codex 実行前の loop 定義検証で拒否する。
- effort は step、agent、`LOOP_CODEX_REASONING_EFFORT`、Codex 既定値の順で解決する。
- Codex adapter は解決済み effort を `model_reasoning_effort` config override として渡す。

## ノンゴール

- agent role や loop の遷移設計を変更すること。
- Codex 以外の adapter に reasoning effort を渡すこと。
- 許可する model 名を schema で固定すること。
- 独立したレビュー反復や補佐ロールを追加すること。

## 背景

`model` は既に agent と llm step の任意文字列属性であり、Codex adapter は step、agent、`LOOP_CODEX_MODEL` の順に解決する。一方、`reasoning_effort` は YAML schema で許可されず、Codex 起動時にも渡されない。値の誤記や型違いを Codex 起動前に検出し、既存の実行処理へ不正値を渡さない。また、development feedback loop では、軽量な Sol を設計と checker に、推論重視の Luna を test と implement に割り当てる。

## 制約事項

- 既存 YAML の互換性を維持し、effort 未指定時は Codex の既定値を使う。
- effort の有効値は `none`、`low`、`medium`、`high`、`xhigh`、`max` のみとする。
- step 指定は同名の agent 指定より常に優先する。
- agent 指定は `LOOP_CODEX_REASONING_EFFORT` より常に優先する。

## 解決する課題

- ロールや step 単位で速度・品質・コストの配分を選べない。
- 不正な effort が実行時まで検出されない。

## 提案する設計

### YAML contract

`agents.<id>` と `steps[]`（`kind: llm`）に任意の文字列 `model` と `reasoning_effort` を置けるようにする。`model` は既存どおり adapter に委ね、`reasoning_effort` は schema が許可値を検証する。標準の development feedback loop は次の割当を agent 設定に持つ。

| role | model | reasoning effort |
| --- | --- | --- |
| design | `gpt-5.6-sol` | `high` |
| test | `gpt-5.6-luna` | `xhigh` |
| implement | `gpt-5.6-luna` | `xhigh` |
| checker | `gpt-5.6-sol` | `high` |

```yaml
agents:
  implement:
    adapter: codex
    model: gpt-5.6-luna
    reasoning_effort: xhigh

steps:
  - id: implement
    kind: llm
    agent: implement
    reasoning_effort: high
```

### 解決順と Codex adapter

Codex adapter は次の順で非空の `reasoning_effort` を解決する。step と agent の双方に指定がある場合は、step の値だけを採用する。

1. `step.reasoning_effort`
2. `agent.reasoning_effort`
3. `LOOP_CODEX_REASONING_EFFORT`
4. 指定なし（Codex の既定値）

解決値がある場合だけ、Codex command の引数へ `-c` と `model_reasoning_effort=<value>` を追加する。subprocess へは `-c` と `model_reasoning_effort=<value>` を別々の引数として渡す。値がない場合は override 自体を追加しない。`model` の既存の step、agent、`LOOP_CODEX_MODEL` 解決順は維持する。

### 検証と設定例

schema は agent と `kind: llm` の step の双方で `reasoning_effort` を任意の文字列属性として受け付ける。ただし値は `none`、`low`、`medium`、`high`、`xhigh`、`max` の集合に限定し、文字列以外または集合外の値は `validate_loop_definition` が `ValueError` として拒否する。`run_loop` は loop 定義を読み込んだ直後、step 実行や Codex 起動より前にこの検証を呼び出す。未指定は許可し、Codex の既定動作を妨げない。development feedback loop の割当は agent を参照する既存の step 遷移を変えず、YAML の model / effort 属性だけで表現する。

## 採用しなかった案

- 任意の effort 文字列を Codex に渡す。
  - YAML の誤記を早期に検出できないため採用しない。
- effort を environment variable だけで指定する。
  - role/step 単位の使い分けができないため採用しない。

## 検証計画

- agent/llm step の effort 許可と、不正な文字列・型の loop 定義拒否を schema テストで確認する。
- Codex command の override 追加、未指定時の省略、step/agent/environment の優先順位をテストする。特に agent 指定が環境変数を上書きすることを確認する。
- development feedback loop を読み込み、design/checker が `gpt-5.6-sol/high`、test/implement が `gpt-5.6-luna/xhigh` であることを確認する。
- 追加したテストと `task ci:test` を実行する。
