# LLM精度検証

LLMを含む処理の出力精度を、人手に頼らず再現可能に計測する。
プロンプト・モデル構成の変更を回帰検知し、精度と速度のトレードオフを定量化して構成を選ぶ。

## 方針

- 実行基盤は Promptfoo に一本化する。
- 通常PRは決定論アサーションのみ、プロンプト・構成変更PRのみスモークjudgeを実行する。
- ナイトリで本番セットを毎日計測し、直近7日移動平均と比較する。
- 異常検出時は再実行（n=3〜5）→原因二分探索→因子分析・校正→修正PR/ロールバックの順で対処する。

## 精度指標

- LLM-as-judge の3段階評価（valid / borderline / invalid）を主とする。
- 見落とし検出を加え、妥当率（valid+borderline）、正確率（validのみ）、見落とし数を併記する。
- 文字列一致・類似度は主指標にしない。決定論アサーションまたは参考値に留める。

## ディレクトリ

```text
eval/
├── README.md                    # 本方針
├── gold/                        # ゴールドセット（入力＋期待出力）
├── rubrics/                     # judge の判定基準・システムプロンプト
├── promptfoo/                   # promptfoo 設定・プロンプト
├── baselines/                   # 採用済み構成の基準スコア（git追跡）
└── results/                     # 採用時スナップショット・校正記録（git追跡）
```

## コスト

- judge は校正済みの Gemini Flash 級を想定し、月間予算上限とキャッシュを設定する。
- 機密データはローカルで処理し、クラウドjudgeへは機密除去済みサンプルのみ送る。
